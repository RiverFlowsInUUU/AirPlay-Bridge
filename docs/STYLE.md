# 对外文档与界面文风

规范对象：**发布说明**（release notes / CHANGELOG）、**README**（人类入口）、
**软件界面文案**。三者读者不同，但共同原则是：**只陈述，不解释。**
想解释的冲动让给 `docs/`。

---

## 发布说明文风（硬性）

发布说明是给用户的，不是开发周记。

**必须**：按 `Added` / `Changed` / `Fixed` / `Removed` / `Deprecated` / `Security`
分组；一条 bullet 一个改动；用户视角（写「修复了 X 时会 Y」，不写「重构了 Z 模块」）；
破坏性变更单独一节且位置显眼；可扫读 —— 用户 10 秒内能判断要不要升级。

**禁止**：第一人称与叙事（「我」「我们觉得」「被指出」「之前偷懒了」）；
解释「为什么这么改」的段落；实现细节（文件路径、函数名、commit hash、PR 编号）；
开篇句式「这一版改了什么」。

正确开头就是直接 `## Added` / `## Fixed` 开列。日期用 ISO 格式，同步更新 `CHANGELOG.md`。

**双语（2026-10-16 起）**：CHANGELOG 每个版本写**两块**，**中文在前、英文在后**，
各自带自己的分组标题。

```markdown
## [1.4.4] - 2026-10-16

**中文**

### 修改

- 中文条目

**English**

### Changed

- English entry
```

**整块分开，不是逐条对照** —— 交错读起来是断裂的，分组标题还会重复出现两次。
CI 的 release notes 提取是「从 `## [版本]` 到下一个 `## [`」，两块都在区间里。

---

## README 文风（硬性）

README 是唯一人类入口。**只陈述，不解释。**

**必须**：开头一句话说清是什么；紧跟安装步骤；特性一行一条；
配置 / 命令 / 参数一律用表格；细节链接到 `docs/`。

**禁止**：解释「为什么这么做」；背景故事与心路历程；
段落式散文（连续超过两行的文字就该改成表格或链接出去）；
内部实现细节；**命令行用法**（用户走 GUI，参数说明只属于 DEVELOPMENT.md）。

**判断标准**：读者扫一遍就知道「这是什么、怎么跑起来、去哪深入」。
想解释的冲动全部让给 `docs/`。

**双语**：

- **`README.md` 是英文**（默认，面向英文用户）；**`README.zh-CN.md` 是中文**
- 两份顶部互相链接
- **改一份必须同时改另一份** —— 结构、小节、表格都要对应
- **行数各自控制在 150 以内**（不是两份加起来）

**Emoji 只限句首**（章节标题、特性条目的开头）—— 句子中间、结尾、正文里一律不要。

## 界面文案与 i18n（硬性）

软件界面支持中英双语，实现见 `src/app/i18n.{h,cpp}`。

**语言范围**：
- **菜单、tooltip、气泡、弹窗、滑块窗口** —— 全部走 `i18n::tr()` / `trw()`
- **`logLine` 的日志内容不翻译** —— 那是排障信息，用户会贴回来，单一语言好搜好对照
- **首次运行的语言选择窗不翻译** —— 那时语言还没确定，用中英并列正文

**接入规则**：
- 词条用**中文原文当 key**（`tr("断开")`），不自造 `menu.disconnect` 这类符号键 ——
  漏翻时原样显示中文，用户看到的是「这句没翻译」而不是「界面坏了」
- `tr()` 返回 `const char*`，**不能直接 `+` 拼接** ——
  带数值的用 `std::string(i18n::tr("延迟")) + "  " + std::to_string(...)`
- 宽字符（`L"取消"`）用 `trw()`，不是 `tr()`
- **编译期常量数组**（档位表 `kXxxLevels[]`）不能直接放 `tr()` —— 在**使用处**就地翻译
- 带参数的气泡文案（`"启动失败: " + err`）**拆成前后缀两条词条**，中间拼参数

**★★★ 改文案后必须全仓库扫旧名** —— 只改菜单一个字，用户会在五个地方看到旧名：

```
弹窗正文、日志、滑块窗口标题（spec.title）、代码注释、README、docs
```

跑：`grep -rn "旧名" --include="*.cpp" --include="*.h" --include="*.md"`
（**排除 CHANGELOG** —— 历史记录不该改）。

**漏翻自检**：启动日志里有 `界面语言: en（词条 N/M）`。
加了新界面文案忘补英文时，这个比值会掉下来。

**验证方法**：界面文案和菜单是模态的、不好截图 ——
**用临时打点把最终文案打出来核对**，验完删掉并 `grep -c` 确认为 0。
**包装正确 ≠ 显示正确** —— 中间还有取值、拼接、覆盖好几道手。

**对外表述的两条硬规矩**：
- **默认屏蔽了的东西，对外文案不能提**（设备列表默认屏蔽 Apple TV 就只写「AirPlay 2 设备」）
- **示例里不许出现看起来像真实的设备名 / 局域网 IP** ——
  用 `<设备名>` / `<设备 IP>` 这种一眼假的写法
